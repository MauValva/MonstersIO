# Monster.io — Final Pacing Report

## Status

The pacing instrumentation is implemented in `src/systems/pacing/session-telemetry.ts`.
This file documents the implementation; the numeric session results must be generated by playing the game because they depend on real player interaction.

## Runtime report

1. Set `PACING_DIRECTOR_CONFIG.debug` to `true` in `src/config/game-config.ts`.
2. Run the game normally and play the desired session.
3. Open the browser console and execute:

```js
window.__monsterDebug.getPacingReportText()
```

For structured data:

```js
window.__monsterDebug.getPacingReport()
```

The report includes the event timeline, first Power-Up, first Evolution, Upgrade introduction, Gold Mine introduction, dead-air periods, empty-map periods, reward intervals and warnings.

## Instrumented areas

- Session phase, activity, intent and intensity.
- Visible and nearby egg density.
- Dead Air and Empty Map detection.
- Micro, medium and macro reward cadence.
- Power-Up spawn and collection.
- Cluster delivery.
- Deposit and Evolution events.
- Upgrade introduction and purchase.
- Gold Mine spawn, activation and completion.
- Fugitive spawn.

## Current design gates

- Opening phase delays macro events.
- First cluster is prepared during the opening window.
- First Power-Up is guaranteed through the real spawn pipeline.
- Gold Mine starts locked and unlocks only after the configured time/progression conditions.
- Upgrade Station is introduced after the second evolution.

## Important limitation

No 5-minute human playtest result is recorded in this repository yet. The report API is ready, but the final timeline and warnings must come from an actual gameplay session.
